# 發佈驗證

正式封裝使用 `build.ps1 -WithUi -ReleaseChecks`。一般開發建置可省略 `-ReleaseChecks`。不得把一般建置稱為通過發佈門檻。

## 執行方式

需要 Rust、Python 3.11 以上、Node.js 與 Chrome。瀏覽器工具只供測試，不隨應用程式發佈，也不需要全域安裝：

```powershell
npm install --prefix .test-tools --no-save @playwright/cli@0.1.23
./build.ps1 -WithUi -ReleaseChecks
```

依序檢查 JavaScript 語法、主程式與 Tauri 的 Rustfmt／測試／Clippy、兩個 release 建置，再執行以下門檻。任一步失敗即停止，通過前不更新 `dist`。

| 門檻 | 測試範圍與通過條件 |
|---|---|
| 單元與整合 | 編碼、舊格式、備份、設定交易、失敗還原、外部設定同步、示範隔離、24 個舊 HTTP 入口、原生視窗 URL 與導覽限制 |
| API 資安 | 未授權／錯誤權杖、Host／Origin、路徑穿越、FN 保護、錯誤型別、超大本文、CSP 與權限政策、停止傳送本文後的逾時恢復。無效請求不得改變鍵盤快照 |
| 壓力 | 32 個併發客戶端、每輪 4,000 次混合讀寫、共兩輪。每輪 P95 小於 1,000 ms、總時間小於 90 秒。同併發暖機後，保留的私有記憶體增量小於 64 MiB、Handle 增量小於 24。量測前等待閒置工作執行緒回收。檢查正常還原與退出 |
| 瀏覽器 | 主要操作流程、原生檔案選擇器與還原確認／取消、燈效與系統設定、過期狀態拒絕、主題持續性、八頁／五組寬度與主題的 40 次版面檢查。側欄文字可見、對比至少 4.5:1、無溢位或 JavaScript 錯誤。缺少明確 pass 回傳不算通過 |
| 相依弱點 | Cargo 鎖定的 Windows x64 MSVC／GNU 可達相依圖，包含建置相依，向 OSV 查詢公告。任何未撤回命中或查詢失敗均阻止發佈。不設定忽略公告清單 |

報告位於 `target/release-checks`，通過後將三份摘要複製到 `dist/validation`。資安／壓測報告記錄實際受測主程式的 SHA-256，封裝前必須核對相同位元組。

## 範圍

測試自動啟動帶有 `--demo --headless --data-dir` 的獨立程式，不連接使用者正在執行的服務。示範模式隔離 HID 與 WASAPI，使用模擬頻譜。瀏覽器測試不使用攝影機或麥克風。

這是本機桌面程式的回歸與安全測試，不是第三方滲透測試認證，也不能保證沒有未知弱點。本文逾時檢查驗證停止傳輸時的恢復，不宣稱涵蓋所有持續滴送或作業系統資源耗盡攻擊。原生 Windows 視窗的視覺檢查與標題列互動，和瀏覽器模擬 Tauri 外殼的測試分開記錄。本版硬體效果沿用先前證據，不冒充本次重新實測。
