# B87 實機自動測試

## 0.8.1：側燈與系統設定

- 實體 Fn＋Insert 切色時，僅 payload[18] 改變，使用者確認側燈換色；觀察到 10→0 循環。軟體提供依鍵盤順序編號的 11 個選項，不推定每項的 RGB 名稱。另寫入 0、2、8、10 並讀回還原，鏡頭未完整涵蓋側面，不把影像當成每色校準。
- Fn＋Win 兩次僅改變 payload[15]：0→1→0。Fn＋S／A 僅改變 payload[0]：0→1→0。
- 使用 0.8.1 release 的 `/api/keyboard` 一次合併設定上述三欄位，讀回完全相符，其餘燈效及四層映射保持原值；測試後再次核對，全部還原為該輪起始快照。未自動驗證 Win 鍵阻擋及 Mac 模式下的實體鍵輸出。
- 機內背光選擇、錄製／儲存等八種功能碼來自目前鍵盤 Fn1 層。離線測試確認可指派及讀回，保留其他按鍵與燈效；沒有按新指派實體鍵錄製，也沒有更新原機內圖樣。Fn＋1／2／3 的後續操作未取得獨立可歸因快照，不據此擴充直接 USB 控制。
- 持續讀取完整設定時，使用者回報延遲、重複輸入與持續閃燈；停止監測後回覆已恢復正常。診斷範例改為手動觸發單次擷取。後續只做少量合併交易；程式閒置不輪詢映射及燈效。
- Rust 共 35 項測試通過。Playwright 新增 7 項鍵盤流程，加上既有 6 項燈效流程，全部通過。新控制項另檢查 1320／1030×860 的 4 個頁面，8 次無 JavaScript 錯誤或橫向溢位。

以下為 0.8.0 的完整實機驗證紀錄。

日期：2026-11-09。裝置：USB `258A:0199`、release `2010`、四層映射。使用者確認背面開關為 USB 有線位置。攝影機為 AVerMedia PW310P，取像 1280×720；未錄製麥克風音訊。

測試使用正式 Rust release 執行檔與隔離資料夾，沒有使用模擬裝置。設定寫入前保存快照；每輪結束讀回核對映射及燈效，並恢復該輪開始時的設定。

## 實體 Fn 操作找到並修正的問題

使用者回覆已短按 Fn＋Scroll Lock 後，唯讀比對確認四層映射不變、payload[10] 仍為 11，只有 payload[9] 從 1 變成 0。鏡頭同時可見內建背光發亮。

進一步以相同綠色模式測試 0→1→0，確認 payload[9]＝0 才選用內建模式；1 會顯示另一組背光圖樣。修正前介面只寫 payload[10]，因此可能「讀回模式正確，實際仍顯示另一配置」。修正後會同步選擇內建配置，並將非零配置顯示為「鍵盤背光配置」，不誤標記憶中的內建模式為使用中。

新增 `scripts/check-lighting-ui.js`，使用真實瀏覽器與隔離示範主程式，確認辨認另一組配置、記憶模式相同時仍可套用且切回內建路徑、關燈、重新啟用；另確認只改 Tap 會保留原始防抖值 3，且明確選擇防抖模式時仍能寫入。六項通過。這份測試會拒絕連到真實裝置，以免日後誤操作；實際欄位生效另由上述 B87 與 webcam 實測確認。

防抖原始值不在介面已知的 1／4 時，以混合狀態顯示並保留原值；只有使用者實際調整防抖控制項才寫入此欄位，避免套用 Tap 連帶改變防抖。

## 未做的破壞性或無法還原測試

- 未覆寫鍵盤的巨集緩衝區或色票表，因為目前無法可靠讀回原始內容。
- 未執行恢復出廠、韌體更新、ISP 或 DFU。
- 未切換／重配使用者的藍牙與 2.4G 連線，未修改 Windows 開機啟動、音量或音效裝置設定。
- 沒有把軟體合成鍵盤事件當成真實鍵盤按鍵輸出的證據。

可重用的唯讀 Rust 診斷程式位於 `examples/hardware_probe.rs`、`examples/lighting_watch.rs` 與 `examples/audio_probe.rs`。前兩者需要實際 B87；音訊診斷只輸出強度與主峰，不保存聲音內容。
